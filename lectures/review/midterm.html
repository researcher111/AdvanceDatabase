1. Which buffer frame can be reused?

A two-frame buffer pool contains block A (pin count 1, clean) and block B (pin count 0, dirty). Block C exists on disk but is not cached. A caller requests C. Assume ordinary page reads and write-back on dirty eviction.

Predict: which frame can be reused? How many disk reads and writes does this request need? What changes if B is also pinned?

Reveal the explanation

B is the only unpinned candidate. The buffer writes B’s dirty contents once, reads C once, and pins C for the caller. A remains in place even if it is older. If both frames are pinned, neither can be replaced. The request cannot complete until a frame becomes available. A cache hit requires no additional disk read.

A pin count tracks active users. A dirty flag identifies a modified page. The eviction policy selects among eligible frames. It cannot select a pinned frame.

2. Where are the bytes?

Use 128-byte blocks and 24-byte fixed-size slots. Each slot contains a four-byte flag, four-byte ID, name field, and four-byte GPA. The name field reserves four length bytes and eight content bytes. Slot numbers start at zero.

Predict: how many complete slots fit? Where does slot 3’s GPA begin? Does deleting slot 1 move slot 3? Does a RID permanently identify a student?

Reveal the explanation

Five complete slots fit, leaving eight unused bytes. GPA starts at offset 20 within a slot. Slot 3’s GPA therefore starts at 3 × 24 + 20 = 92. Deletion changes the slot’s in-use flag without moving other slots.

A RID is (block number, slot number). Reusing a deleted slot gives the address to a different row. A RID is not a permanent student ID. Deletion must also maintain index entries that refer to the deleted row.

3. What does one call to next() do?

The heap scan visits (ada, 31), (ben, 34), then (eli, 36). Use the Lab 5 scan-based plan for:

SELECT name FROM students WHERE gpa > 35;

Predict: draw the operators. What happens when the caller asks the root for its first result? Which stage recognizes tokens, and which stage constructs scans?

Reveal the explanation

The scan tree is ProjectScan(name) → SelectScan(gpa > 35) → TableScan(students). Selection advances past ada and ben, then accepts eli. Projection exposes the name field. The first successful root call returns eli after inspecting three input rows.

The lexer identifies tokens. The parser creates a statement representation. The planner constructs the scan tree. Parsing does not read result rows.

Follow-up: a complete nested-loop product has three outer rows and two inner rows, with no early termination. How many candidate pairs are considered?

Reveal the work count

The product forms six candidate pairs. A predicate can reject pairs, so the output count can be smaller. Six comparisons do not imply six disk reads. Pages can be cached, and multiple rows can share one page.

4. Follow the tree all the way to a row

Predict: which child receives key 36? For the inclusive range 31–37, where do we start and stop? What extra work follows a matching leaf entry?

Reveal the lookup and range

Equality with separator 36 goes right. The separator is a routing boundary. The leaf entry supplies the RID list. Those addresses locate heap rows.

For 31–37, descend to the left leaf. Start at 31. Follow the next-leaf link. Accept keys 31, 34, 36, and 37. Stop at 39, which exceeds the inclusive upper bound. Each RID for a matching key can contribute a row.

The matching-key count can therefore differ from the returned-row count.

Count tree-node visits separately from heap-page access and physical disk reads. A visited page can already be in the buffer pool.

Split practice: Start a separate tree with one full leaf [1, 2, 3, 4] and capacity four distinct keys. Insert 5 with the lecture’s middle-split rule. Draw the temporary overflow. Draw both resulting leaves, their link, and the new root.

Reveal the split

The temporary leaf is [1, 2, 3, 4, 5]. Split it into [1, 2] and [3, 4, 5]. Link the left leaf to the right. Create root separator [3]. Key 3 retains its RID list in the right leaf, while the root holds a routing copy. The tree now has two levels.

Another RID for an existing key extends that key’s RID list in this model. It does not consume a distinct-key slot. An internal-node split moves a separator upward. A leaf split copies its boundary key upward.
