1. Which page can move?

A two-frame buffer pool contains block A (pin count 1, clean) and block B (pin count 0, dirty). Block C exists on disk but is not cached. A caller requests C. Assume ordinary page reads and write-back on dirty eviction.

Predict: which frame can be reused? How many disk reads and writes does this request need? What changes if B is also pinned?

Reveal the explanation

B is the only unpinned candidate. Write its dirty contents back once, read C once, and pin C for the caller. A remains in place even if it is older. If both frames are pinned, neither is an eligible victim; the request cannot complete until a frame becomes available. A cache hit would not need another disk read.

A pin count tracks active users. A dirty flag records a modified page. An eviction policy chooses among eligible frames; it cannot make a pinned frame eligible.

2. Where are the bytes?

Use the lecture’s 128-byte block and 24-byte fixed-size slots. Each slot contains a four-byte flag, a four-byte ID, a name field reserving four length bytes plus eight content bytes, and a four-byte GPA. Slot numbers start at zero.

Predict: how many complete slots fit? Where does slot 3’s GPA begin? Does deleting slot 1 move slot 3? Does a RID permanently identify a student?

Reveal the explanation

Five complete slots fit, leaving eight unused bytes. GPA starts at offset 20 inside a slot, so slot 3’s GPA begins at 3 × 24 + 20 = 92. Deletion changes the slot’s in-use flag without moving other slots.

A RID is (block number, slot number). Reusing a deleted slot can give the same address to a different row; a RID is not a permanent student ID. Any index entries referring to a deleted row must be maintained consistently.

3. What does one call to next() do?

The heap scan visits (ada, 31), (ben, 34), then (eli, 36). Use the Lab 5 scan-based plan for:

SELECT name FROM students WHERE gpa > 35;

Predict: draw the operators. What happens when the caller asks the root for its first result? Which stage recognizes tokens, and which stage constructs scans?

Reveal the explanation

The scan tree is ProjectScan(name) → SelectScan(gpa > 35) → TableScan(students). Selection advances its child past ada and ben, then accepts eli. Projection exposes the name field. The first successful root call therefore yields eli; the scan has inspected three input rows.

The lexer recognizes tokens, the parser builds a representation of the statement, and the planner constructs the scan tree. Parsing a statement does not read its result rows.

Follow-up: a complete nested-loop product has three outer rows and two inner rows, with no early termination. How many candidate pairs are considered?

Reveal the work count

Six candidate pairs. A predicate can reject pairs, so the output count may be smaller. Six comparisons do not imply six disk reads: pages can already be cached, and several rows can share a page.

4. Follow the tree all the way to a row

Predict: which child receives key 36? For the inclusive range 31–37, where do we start and stop? What extra work follows a matching leaf entry?

Reveal the lookup and range

Equality with separator 36 goes right. The separator is a routing boundary; the leaf entry supplies the RID list, whose addresses lead to heap rows.

For 31–37, descend to the left leaf, begin at 31, and follow the next-leaf link. Accept keys 31, 34, 36, and 37; stop at 39 because it exceeds the inclusive upper bound. Every RID for a matching key can contribute a row, so the number of matching keys need not equal the number of returned rows.

Count tree-node visits separately from heap-page access and physical disk reads. A visited page can already be in the buffer pool.

Split practice: start a separate tree with one full leaf [1, 2, 3, 4], capacity four distinct keys. Insert 5 using the lecture’s middle-split convention. Draw the temporary overflow, both leaves, their link, and the new root.

Reveal the split

The temporary leaf is [1, 2, 3, 4, 5]. Split it into [1, 2] and [3, 4, 5], link the left leaf to the right, and create root separator [3]. Key 3 remains in the right leaf with its RID list; the root holds a routing copy. The tree now has two levels.

Inserting another RID for an existing key extends that key’s RID list in this teaching model; it does not consume another distinct-key slot. When splitting an internal node, distinguish moving a separator upward from copying a leaf boundary.
