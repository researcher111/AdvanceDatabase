Use the course repository and Python 3.11 or newer. The two input files already ship with Lab 8; no data download, account, or API key is needed. Run these commands from the repository root:

macOS / Linux:

Windows PowerShell commands 
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r lectures/lecture-10/discovery/requirements.txt
.venv\Scripts\python.exe lectures/lecture-10/discovery/discovery.py --serve

Open the local SQL workbench on port 8770. It creates lectures/lecture-10/discovery-data/taxi.duckdb, checks row counts and unique keys, and lets you edit and run the queries below. Press Ctrl-C in the terminal to stop the server; your database stays on disk. Rerunning reuses it. Choose a fresh --database PATH for a separate copy.

The website version shows results already computed from the same SQL and sample. The local workbench executes your edits against the loaded database. Changes to a result are observations to explain, not automatic evidence of a cause.

One observation = one ride.

There is one RID-like identifier per trip, not one per passenger, driver, or vehicle. This sample contains no driver identity, so it cannot measure driver income or earnings per shift. fare + tip is the recorded fare-and-tip subtotal; it excludes tolls and other charges and is not profit.

The loader defines primary keys, imports the compressed CSV and zone lookup, and creates a view with two left joins. Inspect the exact setup in discovery.py. For a Python notebook, connect with duckdb.connect('lectures/lecture-10/discovery-data/taxi.duckdb', read_only=True) from the repo root, then use con.sql("SELECT * FROM trips LIMIT 5").show().

What was sampled, cleaned, and left out?

The bundled course sample contains 5,000 trips per month from the 2024 yellow-taxi files (sampling seed 6042). The course preparation retained 1–6 passengers, 0.1–100 miles, fare $1–$500, recorded tip $0–$200, card or cash payment, and duration 1–180 minutes. These filters define the population represented here. See the sample documentation, the compressed rides, and the zone lookup.

Equal monthly sample sizes do not preserve citywide monthly counts. Cash tips are not captured in the recorded tip field. A zero can describe a missing measurement mechanism. These are observational records with cleaning and sampling decisions, not a randomized experiment.

3. Turn a result into a discovery

First session, 75 minutes: 10 minutes to load and audit the database; 10 to predict and investigate the monthly sample; 15 to challenge the tipping conclusion; 15 to compare airports and change the metric; 15 for a pair to choose a neighborhood, route, or join investigation; 10 to exchange conclusions and propose a competing explanation.

During the analytics lecture, use the first two cases as a short opening demonstration. Use the full sequence in the discovery workshop. These investigations are ungraded and do not replace Lab 8’s eight required SQL queries.

  1. State a unit: a sampled trip, route, zone, or month. Check that joins preserve it.
  2. Show the denominator: count the records behind a percentage or comparison.
  3. Try to break your explanation: change a distance range, destination, payment filter, or aggregation.
  4. Write a cautious claim: “In this cleaned sample…” is different from “New Yorkers always…”
  5. Make it reproducible: save the SQL, result, units, and next question. Do not keep only the chart.
