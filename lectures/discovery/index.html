Instructor preparation · about 15 minutes, no server administration
  1. Open each hosted service from the teaching network. Run one case query. Inspect its schema and row count.
  2. Use the dated JSON/CSV snapshots as the common class baseline. Live results can change. Record the retrieval time.
  3. To refresh them, run python3 lectures/discovery/refresh.py from the course repo. It uses Python’s standard library and four small read-only requests. Run it during preparation, not on every student page load.
  4. Have students download the evidence before class if internet access is uncertain. The page itself draws the saved charts without a network call.
  5. Keep a copy of the query, result, source URL, retrieval date, row definition, and any exclusions with each conclusion.

Private uploads, persistent student tables, or dedicated capacity would require additional setup. A managed ClickHouse Cloud classroom database could use the same SQL. We would select a budget and account owner, load a limited taxi/weather subset, and provide read-only access. The provider would manage the infrastructure. The course would manage classroom data and access. This outline has created no resources or charges.

Case 1 · Thursday November 19 · Minutes 0–25

The city that never sleeps?

“More taxi trips happen on weekdays, so New Yorkers go out less on weekends.” The editor wants to publish. Do we sign off?

Predict: Which hours change most after dividing by the number of observed weekdays or weekend days? Sketch both curves before viewing results.

Data: filtered yellow-cab trips from the hosted July 2015 table. This extract differs from the bundled 2024 sample. Compare day types within this extract. Do not compare counts across these datasets. Each result row represents one hour/day-type pair. Retain its observed-date count with the total.

  1. 0–5 · The headline. Recall the taxi sample: why were all months equally busy?
  2. 5–10 · Meet the witnesses. Inspect dates, cab type, filters, and observed-date counts. Predict a weekend curve.
  3. 10–20 · Follow the query. Filter trips → group by day type/hour → count distinct dates → divide. Reveal totals, then switch to trips per observed day.
  4. 20–25 · Record the conclusion. State one finding and one limitation with a partner. Propose a different month or distance band. Then examine the weather case.
Teaching reveal and visual plan

Show one trip entering an hour group. Then show the calendar dates that supply its denominator. The saved chart compares totals with trips per observed day. Weekday groups contain 23 dates, and weekend groups contain 8 dates in July 2015. An hour with no records contributes no date to that denominator. Check coverage before describing calendar-day rates.

A taxi ride does not represent a person. Activity does not measure happiness.

Systems link: column scans, filter pushdown, aggregation, and the difference between elapsed time and work done. Ask which columns the engine needs to read.

Cliffhanger: perhaps weather explains the pattern. Can we trust the weather table?

Case 2 · Thursday November 19 · Minutes 25–55, then question swap

The July that froze?

The next chart reports a zero average temperature for every July day in Central Park. Did the city freeze? Could the data pipeline explain the zeros?

Predict: list two explanations for zero. Which extra field or source document could distinguish them?

Data: NOAA GHCN-Daily observations from the ClickHouse mirror for station USW00094728, July 2015. Each row represents a station/date pair. Temperature fields use tenths of °C. The query converts units and retains encoded zeros.

  1. 25–30 · The impossible chart. Reveal only encoded_avg_c. Students predict two explanations.
  2. 30–40 · Compare other fields. Reveal minimum and maximum temperatures. Inspect the schema and source preparation.
  3. 40–50 · Reconstruct the pipeline. Draw observation rows → quality filtering → pivot → station/date row. Explain how an absent element can become a numeric default.
  4. 50–55 · Design the next test. Before joining to daily taxi aggregates, name the key, date-coverage, and time-convention checks needed.
  5. 55–75 · Project question swap. Exchange the ten evaluation questions already due today. Label questions that need numeric evidence, retrieved text, or an explicit “unknown.”
Teaching reveal and visual plan

The saved chart first displays the suspicious average. It then adds recorded minimum and maximum temperatures. Compare NOAA’s original missing-value and flag definitions with the mirror’s pivot using anyIf. Its numeric default can combine absent observations and actual zeros. Do not replace all zeros with NULLIF. Zero °C and zero precipitation can be actual observations.

Systems link: sparse observations, wide rows, schema design, defaults, and joins that preserve row meaning. A taxi/weather scatterplot is an optional follow-up design. This page does not supply that chart or establish causation. Use the same 2015 dates. Do not join this mirror to the 2024 sample by month and day alone.

Cliffhanger: if observation rules can change a weather chart, what might they do to a census of planets?

Case 3 · Tuesday November 24 · 75 minutes

The planet census

One detection method accounts for many more cataloged planets than another. Does this show the universe’s population? Could it instead show which planets our instruments detect?

Predict: should every discovery method have the same proportion of planets with a radius value? What does COUNT(column) leave out?

Data: NASA Exoplanet Archive’s pscomppars table, with discovery years 1990–2024. It contains one composite row per planet. Values can come from different references or calculations. A non-null radius does not necessarily represent a direct measurement. A discovery-year cutoff does not prevent later catalog revisions.

  1. 0–10 · Choose the headline. Teams predict the most common recorded method and the weakest conclusion one might draw from it.
  2. 10–25 · Choose the row. Compare the composite table’s planet grain with the ps table’s multiple parameter sets.
  3. 25–40 · Make a census. Run the grouped count. Switch the saved visual from catalog counts to radius-value coverage.
  4. 40–60 · Change the selection. Change the year range, or inspect one method’s missing values. Design a period–radius plot with logarithmic axes and an explicit eligibility filter.
  5. 60–75 · Peer review. Trade a claim and an alternative explanation. Name the detection-efficiency information needed before estimating the underlying population.
Teaching reveal and visual plan

Start with a bar for the full catalog count. Split it into rows with and without radius values. Switch to percentages. Do not replace missing radii with zero. For the optional scatterplot, identify excluded nulls, uncertainty, upper/lower-limit flags, and calculated radii.

Catalog counts require a selection model before they can estimate planet frequencies in the universe.

Systems link: table grain, null-aware aggregation, metadata catalogs, and reproducible snapshots. Composite-table documentation and column definitions are part of the evidence.

Cliffhanger: a name such as TESS appears in our research. How do we connect it to organizations and sources without trusting a name match?

Case 4 · Tuesday December 1 · 30 minutes + 45-minute project rehearsal

Who says so?

Our research assistant produces a fluent sentence about TESS. Can we trace each part of the sentence to an identifiable statement and a source?

Predict: if a graph lists two operators, is that a contradiction? If one statement has no attached reference, is it false?

Data: Wikidata’s TESS entity Q1323537, its operator statements, and attached references. One output row is a statement/reference combination, not a distinct mission. An optional URL may be empty even when another kind of reference is present.

  1. 0–10 · Follow one edge. Query mission → operator with the entity ID. Draw the returned organizations.
  2. 10–20 · Inspect the references. Reveal statement IDs and reference nodes. Compare one claim with an official mission page. A graph edge identifies a claim to investigate.
  3. 20–30 · Check the answer. Write a sentence with its source. Record an unanswered question. Explain how optional references can produce additional rows.
  4. 30–75 · Rehearse the project. Show one supported answer and one retrieval failure. Peers follow the citations and propose a better question.
Teaching reveal and visual plan

Draw mission → operator. Inspect statement IDs. Reveal whether each statement has attached references. Follow source or import URLs in the results. The Wikimedia import URL records the statement’s origin. It is not an independent scientific source.

One saved reference points to a Wikipedia revision. Compare that reference with official mission documentation before stating a claim. A missing reference does not prove that a relationship is false.

Systems link: RDF triples, SPARQL and SQL, identity resolution, one-to-many joins, and RAG citation quality. The mapping from the archive’s facility name to Q1323537 uses manual verification. It is not an automatic string join. The limited query avoids a complete graph scan. See the service limits.

Case 5 · Thursday December 3 · 75-minute project workshop

The discovery hearing

The editor requires: “Show the query and the uncertainty behind the headline.” Each team brings a project discovery or uses a supplied case for practice.

  1. 0–10 · Seal the evidence. Record the question, SQL/SPARQL, source, timestamp, filters, row unit, and result.
  2. 10–20 · Reproduce it. A partner rebuilds the chart from the CSV. Distinguish a changed live catalog from a changed query.
  3. 20–40 · Challenge it. Test one alternative grouping, denominator, missing-value rule, or retrieval configuration.
  4. 40–60 · Revise the explanation. Show three stages: initial belief → new evidence → supported conclusion. Include a visible limitation.
  5. 60–75 · Finish the project. Work on the report and demo with instructor and TA help. The report remains due December 7. Presentations remain December 8.

The case file

One question. One reproducible query or retrieval run. One readable chart. One competing explanation. One qualified conclusion. One next test.

This is a workshop format for improving the existing project, not a new graded deliverable.

Keep the source with the story

Taxi records originate with NYC TLC. The hosted table follows ClickHouse’s prepared dataset. A transformed mirror supplies NOAA’s GHCN-Daily dataset. Save the selected population and preparation notes with each export.

Planet data come from the NASA Exoplanet Archive, operated by Caltech under contract with NASA. Follow its acknowledgment and citation guidance and cite specific parameter references when using them. Its TAP documentation describes the query interface.

Wikidata’s structured data use CC0. Linked sources have their own terms. Retain entity and statement IDs so another reader can check the claim. These examples investigate existing records. They do not claim new scientific discoveries.
