Vector Databases

Find passages even when their wording differs from the question. Measure what searching fewer vectors can miss, then check the passages.
Daniel G. Graham · UVA School of Data Science

Fictional project example

Maya and Noor test their project at a lab desk. Maya types: How does a database recover after a crash? Their notes contain a passage about replaying a durable log. An exact string search for the question returns no match.

The passage describes recovery without repeating the question. Noor asks, Can we find related passages even when the words differ? They will try vector search, then read the results to check whether the passages answer the question.

A chunk is a passage that the system stores as one search item. An embedding model converts text into a fixed-length list of numbers, called an embedding vector. The question’s embedding is the query vector. Search compares this vector with the stored chunk vectors.

The nearest neighbors are the stored vectors closest to the query under the chosen comparison rule. Exact search compares the query with every stored vector. An approximate nearest-neighbor (ANN) index can compare fewer vectors, but it can miss exact neighbors. In Lab 9 on October 29, you will build an inverted file (IVF) index. You will measure how much work it saves and which neighbors it misses.

Companion reading: pgvector's README (index types and search settings) · the HNSW paper: Malkov & Yashunin, Efficient and robust ANN search using Hierarchical Navigable Small World graphs1 · FAISS's index-choosing guide.

Maya wants the ten chunks with the highest similarity scores for her question. We will save the exact result IDs first. Those IDs let us identify neighbors that an approximate search misses.

A B+ tree locates key 7 in a fixed key order. That order does not rank passages by their similarity to a question. The dot product is 0.8 × 0.6 + 0.6 × 0.8 = 0.96. We will use this score to explain a missed neighbor.

Quiz 7 takes the first 10 minutes. It covers columnar storage and the analytics stack. We then examine the vector index for your project.

Searching fewer candidate vectors can miss exact neighbors. A candidate is a stored vector that the search selects for comparison. The index saves work by leaving some vectors unexamined.

We will follow one sequence: save exact IDs, search fewer vectors, and compare the two result lists. Then we will search more vectors and measure the extra work. Recall tells us what fraction of the exact neighbors the approximate search found.

Finally, read the returned chunks. A high similarity score does not establish that a chunk answers the question.

Find a chunk with different words

A B+ tree on chunk IDs can find chunk 7 or chunks with IDs from 7 to 12. This ID order stays the same for every question.

For the crash-recovery question, Maya wants a chunk about replaying a log. For a question about faster queries, she wants a chunk about indexes. The same chunks need a different ranking for each question.

Vector search calculates that ranking from the query vector. It gives each chunk vector a similarity score and returns the highest scores. The embedding model and comparison rule determine what counts as similar.

A B+ tree supports a fixed key order, and a hash index groups equal keys. Neither lookup directly supplies a ranking that changes with each query vector.

Convert the question and chunks to comparable vectors

Noor encodes the chunks when preparing the index and stores their vectors. When a question arrives, she encodes it with the same model and compatible query settings. Each output has the same number of coordinates. These coordinates locate the input in the model’s vector space. The recovery question and a log-replay chunk can have similar vectors even when their words differ.

How does text become a vector? A typical transformer embedding model first splits text into tokens, which can be words or parts of words. The model represents each token with a vector. It uses information from other tokens to update that vector. It then combines the token vectors into one vector for the input.

The example below combines token vectors by taking their average. This operation is called mean pooling. It then divides the average vector by its magnitude to give it length one. This operation is called normalization. Models can use different pooling methods.1112

Compare the vectors with a similarity score

Return to the opening calculation: (0.8, 0.6) · (0.6, 0.8) = 0.96. Both vectors have length one. For these unit vectors, cosine similarity equals the dot product. A larger score means a closer match under this metric.2

Let n be the number of stored vectors and d their number of coordinates, or dimensions. A query requests the top k vectors by similarity. For unit query vector q and stored vector v:

\[ \text{sim}(q, v) \;=\; q \cdot v \;=\; \sum_{i=1}^{d} q_i\, v_i \]

To use dot products as cosine scores, normalize each stored vector once. Divide each coordinate by the vector’s magnitude, also called its Euclidean norm. Normalize the query vector before searching. Exact search then calculates n dot products per query:

\[ \text{exact cost} \;=\; n \cdot d \text{ multiplications} \]

For one million vectors with 1536 dimensions, each query requires about 1.5 billion multiplications. Additions and result selection require additional work.2

Use the comparison rule recommended for your embedding model. The dot-product examples in this lecture use normalized vectors.

Save the exact search results

Maya compares the query vector with every stored chunk vector and keeps the ten highest scores. Noor saves the ten result IDs. This result is their exact search baseline: the reference list for checking approximate search.

They must use the same vectors, similarity metric, and rule for tied scores when comparing methods. Otherwise, a changed result might come from a changed comparison rule. They must also read the chunks. Exact search identifies the highest scores, but those chunks may still fail to answer the question.

The dot products are independent, so the system can calculate several at once. Parallel execution can reduce elapsed time, but each query still uses every coordinate of every stored vector. More vectors, more dimensions, or more queries per second increase the total work.

Exact search can be sufficient for a small dataset

Exact search is also called brute-force search. For a small dataset, it may already meet the required query time. The project requires this baseline. Use it to evaluate whether an index gives a useful improvement. Compare query time, index construction time, memory use, and missed neighbors.

A count of multiplications describes work, not elapsed time. Measure query time on your hardware before choosing a different search method.

Search fewer vectors

Maya’s exact search checks every vector. Noor suggests grouping the vectors and checking only the groups that appear closest to the query. That reduces comparisons, but a skipped group can contain an exact neighbor. We need to measure what the search misses.

An inverted file (IVF) index uses groups called lists. A centroid is the vector used to represent a group. IVF compares the query with the centroids, then searches selected lists. The probe count, written P, is the number of lists searched.

Our examples use IVFFlat: IVF list selection followed by exact scoring of every vector in the selected lists. The approximation comes from skipping lists, not from changing those scores.

Hierarchical Navigable Small World (HNSW) uses a different structure: a graph with stored vectors as nodes. Search follows saved links between nodes to find closer vectors. Both indexes let us change search effort and measure the effect on recall.

Select lists before scoring their vectors

Imagine books grouped on shelves. You choose promising shelves from their labels, then inspect the books on those shelves. A useful book can be on a shelf you skip.

In this comparison, a centroid acts as a shelf label. Its list is the shelf, and each stored vector is a book. Searching two lists is like inspecting two shelves. In the actual index, vector comparisons determine membership and which lists to search. The shelf comparison does not tell us which passages answer a question.

During construction, k-means starts with a set of centroids. It assigns each vector to its nearest centroid. It moves each centroid to the average of its assigned vectors, then repeats the assignment. This process forms the groups before queries arrive.

During search, the lists stay fixed. IVF scores the query against each centroid and selects the P closest centroids. It scores the vectors in their lists. A centroid summarizes its group, so the closest centroid need not have the closest stored vector.

Compare the work for IVF and HNSW

The small example shows both parts of IVF’s work: score centroids, then score vectors in selected lists. Use the same two counts to estimate work for a larger dataset.

IVF searches selected lists

Suppose n = 4,000 vectors are divided among C = 20 equally sized lists. Each list contains 200 vectors. With P = 4 probes, search scores 20 centroids and about 4 × 200 candidate vectors. The estimate is 20 + 800 = 820 comparisons.

In general, C is the number of lists and P is the number searched. Approximately equal list sizes give about n/C vectors per list. Add the centroid comparisons to the candidate comparisons:34

\[ \text{cost} \;\approx\; C + P \cdot \frac{n}{C} \qquad \text{instead of } n \]
4,000 vectors, C = 20, P = 4about 820 vs 4,0004.9× fewer evaluations
1M vectors, C = 1000, P = 10about 11,000 vs 1,000,00090×4

If the search skips a list, it misses any exact neighbors in that list. A larger P adds candidate vectors and increases the work per query.4

Choose the list count when constructing the index. A count proportional to √n is a starting estimate, not a universal setting. Measure different choices on your workload. The 820 estimate assumes equally sized lists. The Lab 9 measurements below use actual lists, which can have different sizes.

HNSW searches through a layered graph

Noor now tries HNSW. Each stored vector becomes a node in a graph. During construction, the index selects nearby vectors and saves links between their nodes. These links give search a set of possible next steps. HNSW nodes represent stored vectors, not IVF centroids.

The bottom layer contains every vector. Upper layers contain fewer vectors, with links that help search move across the dataset. A vector shown in two layers keeps the same ID. Moving down a layer means continuing from that same vector among more nodes and links.

Search starts at an entry node in an upper layer. It follows links toward vectors closer to the query, then moves down. At the bottom layer, a full HNSW search keeps multiple candidates to explore. It can still miss a closer vector if it does not reach that node.

HNSW illustration · sparse upper layer and dense lower layer

This illustration has twelve vectors in two layers. Predict which linked node is closest to the query ★ before each step. The animation follows one path using Euclidean distance. It moves to a closer linked node or moves down when no linked node is closer. At the bottom layer, it stops when no linked node is closer. A full HNSW search explores multiple candidates in that layer.1

The counter records neighbor checks, including repeated visits. It is not a count of every calculation in a full HNSW search. This path finds the nearest neighbor, but HNSW does not guarantee that result for every query. In a full search, ef_search controls the search candidate list size. Larger values permit more exploration, which usually improves recall and increases work.5

Choose a search setting

Maya returns to the ten exact result IDs that Noor saved. If an approximate search returns seven of those IDs, recall@10 is 7 / 10 = 0.7. The other three exact neighbors are missing. Recall measures the fraction found, regardless of their returned order.

Use the same vectors, metric, and tie rule for both searches. For a request for k neighbors, count the shared IDs and divide by k:

\[ \text{recall@}k \;=\; \frac{\bigl|\, \text{approximate top-}k \;\cap\; \text{true top-}k \,\bigr|}{k} \]

Recall of 1.0 means that the index found all k exact neighbors. At a fixed k, average recall of 0.75 means one quarter of the exact neighbors were missed across the query set.6

Calculate recall@10

Exact search returns IDs {1…10} as the top-10 neighbors. At probe 2, IVF returns these IDs in order: 1, 2, 3, 5, 6, 8, 9, 11, 14, 20.

Both searches use the same vectors, metric, and tie rule. This IVFFlat index scores every vector in each selected list exactly. Calculate recall@10. Determine whether IDs 4, 7, and 10 are in searched lists or skipped lists.

Show answer

The shared IDs are {1, 2, 3, 5, 6, 8, 9}, so recall@10 = 7 / 10 = 0.7. IDs 11, 14, and 20 do not count because they are outside the exact top 10. The missing exact IDs 4, 7, and 10 must be in skipped lists. If their lists were searched, their scores would place them in the top ten.

A larger probe count adds lists and retains previous candidates. If scores stay fixed and tie handling stays consistent, recall cannot decrease. The Lab 9 test harness checks this property.4

Where to run a vector index

Maya edits chunk 42 after building the index. Its stored vector still represents the old text. The application must embed the new text and update entry 42. Otherwise, search compares the question with an outdated representation.

Where should that index live? It can run inside a database, inside an application, or in a separate service. Every choice must preserve the connection between vectors and source chunks. Storing the index in the database does not automatically create new embeddings when text changes.

Products differ in filtering, durability, and operational tools as well as index types. Some compress vectors with quantization, which represents values with fewer bits. Compare these features with your workload and update process.

FAQ

Why cosine instead of Euclidean distance?

Cosine similarity compares direction without depending on vector length. For unit vectors, cosine similarity and Euclidean distance give equivalent rankings because ‖q−v‖² = 2−2q·v. A larger cosine score then corresponds to a smaller Euclidean distance. Use the model’s recommended metric. Normalize vectors consistently when using dot products as cosine scores.2

Is recall the only quality metric that matters?

No. Recall against exact search tells you whether the index found the same neighbors. Even exact neighbors can contain irrelevant text. Check whether the passages supply useful evidence, then check whether a generated answer follows that evidence. The next lecture separates these evaluations.

When is a separate vector service useful?

A separate service can help when you need managed scaling, isolation between customers, or specialized search features. It adds network requests and another store that must track source updates. Compare these costs and benefits with an index in your existing database.10

Could microdb have a vector index?

Yes. An IVF list could store (centroid_id, RID) entries. Search would select lists and score their vectors. It would return RIDs for matching table rows. Lab 6 IndexSelectScan shows this index-to-table lookup pattern.

Similarity ranking would require additional logic. A team that continues microdb could implement this project extension.3
