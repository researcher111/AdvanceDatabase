Advanced Databases for Data Science

Daniel G. Graham · Lectures, labs & discovery workshops · follow the revised schedule · 75-minute sessions

Every query you have ever run sat on top of machinery you were never shown: pages on disk, a buffer pool deciding what stays in memory, an optimizer guessing row counts, a write-ahead log promising your commit survives a crash. This course shows you that machinery the most honest way possible: you build it. Over the first six teaching weeks you write microdb, a working relational database engine in Python, one subsystem per lab, in the spirit of Edward Sciore's SimpleDB. Then you take the same ideas into the systems data scientists live in every day: DuckDB and the columnar world, vector databases, MapReduce and its heirs Spark & Ray, Google's Bigtable, graph engines. You finish by building a retrieval-augmented-generation (RAG) pipeline as your team project.

The course in three acts

Act I

Build the engine

Six required labs, one engine. You write microdb's file manager, buffer pool, record pages and catalog, iterator-model operators, SQL front end, and B+ tree index. Transactions and recovery are optional bonus extensions.

Weeks 1–6 · midterm Oct 22

Act II

Widen the lens

With the internals in your hands, the modern landscape stops being magic: why DuckDB wins scans by 100×, how a vector index trades recall for speed, how MapReduce became Spark and Ray, why Bigtable partitions the way it does, and when a graph traversal beats a join.

Analytics starts Oct 8 · discovery workshops in November

Act III

Ship a RAG pipeline

Your team builds a retrieval-augmented-generation system in Python over a corpus you choose: chunking, embedding, a vector index you understand because you built one, and an evaluation that proves it works.

Proposal Oct 29 · retrieval Nov 12 · question swap Nov 19 · demo Dec 8

microdb: the engine you build

Each core lab adds one layer, bottom-up, and each layer runs on the ones below it. By Lab 5 microdb answers real SQL; Lab 6 adds indexed access. The optional Lab 7 explores crash recovery. Starter code for each lab ships with a reference implementation of every layer below it, so no one is stuck on week 3 because of week 2.

What you'll be able to do

  • Explain, and demonstrate in code you wrote, what a database does between receiving SQL text and returning rows.
  • Read an EXPLAIN ANALYZE plan and fix the slow query it describes.
  • Choose the right engine for a workload (row store, column store, vector, graph, wide-column, or warehouse) and defend the choice with measurements.
  • Scale past one machine deliberately: partition data (hash vs range), trace the map → shuffle → reduce pattern, and parallelize real work with PySpark and Ray.
  • Build and honestly evaluate a production-shaped RAG pipeline: chunking, embedding, ANN retrieval, generation, and retrieval metrics.
  • Reason about transactions, isolation anomalies, replication, and what CAP does and doesn't let you have, using Bigtable and the optional transaction readings.

Follow a discovery from question to evidence

The discovery bureau connects five cases across four meetings: city rhythms, a suspicious weather record, a planet census, a source-tracing graph, and a final discovery hearing. Each includes a timed outline, verified query, saved visual evidence, and a next question. The public databases are already hosted and loaded; see the setup guide.

Get the code

Every lab page has download buttons for its individual files, but the whole course is one clone. Starter code and test harnesses live in labs/lab-NN/starter/:

git clone https://github.com/researcher111/AdvanceDatabase.git
cd AdvanceDatabase/labs/lab-01/starter
python3 test_filemanager.py        # 0/9 passing is the correct starting state

Labs 1 to 7 are cumulative, so each starter/ folder ships a working reference implementation of every layer below the one you are building. Pull before each lab to pick up that week's files. Reference solutions and answer keys are not in this repository.

Logistics

  • Prerequisites: comfortable Python and basic SQL (SELECT / JOIN / GROUP BY). No systems background assumed; that's what the course builds.
  • Tools: Python 3.11+, PostgreSQL, DuckDB, PySpark, Ray, Kuzu (demo). Local labs use Python packages and their documented dependencies. Spark and Ray run in local mode. Discovery sessions use public hosted ClickHouse, NASA TAP, and Wikidata queries; no new account or server is required.
  • Texts: no required purchase. Readings drawn from Sciore's Database Design and Implementation (SimpleDB) and course notes; every lab page is self-contained.
  • Sessions: 75 minutes. Quizzes open the indicated lectures. Labs are working sessions; dates and submission deadlines follow the revised schedule.
