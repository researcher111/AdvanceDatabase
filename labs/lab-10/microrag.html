micro-rag · build a retrieval pipeline

Implement retrieval and prompt assembly, then test whether the pipeline selects the source passages needed to answer each question.
Daniel G. Graham · UVA School of Data Science

A language model may produce a fluent answer even when the retrieved passages do not support it. In this lab, you will build the retrieval and prompt-assembly stages of a RAG pipeline, then test whether they supply the right evidence. The starter provides the chunker, embedder, Lab 9’s index implementation, and a generation function. Its default echo mode prints the assembled prompt without calling a model. A 12-question evaluation set checks retrieval quality independently of generation.

Builds on: Lab 9 · microvector (shipped as a reference implementation in this starter) · Lewis et al., Retrieval-Augmented Generation · the embedder is scikit-learn's HashingVectorizer feature-hashing approach, implemented with the Python standard library.

This embedder uses feature hashing and stop-word removal. It can match shared words, but cannot reliably connect synonyms. A learned embedder can replace it while keeping the pipeline interfaces; rebuild the stored vectors and rerun evaluation when making that change.

  Required chunk and prompt formats
  
A chunk contains doc, title, and text fields. Retriever.retrieve(question, k) returns the top k chunks in descending score order, adding a score to each returned copy. build_prompt creates three sections separated by blank lines: the required header, one [doc] Title: text line per chunk, and the final Question: … line. Match the module docstring’s format exactly; the prompt tests check these separators and labels.

  Exercise · read the failure
  
A classmate’s QUALITY tests fail with hit@3 near zero, even though the returned scores look plausible. One own-text check happens to pass. What mapping between the index and the chunks would you inspect first?

  
Show answer
  
Check whether the vectors were built in a different order from self.chunks, for example after sorting or deduplicating the input. Then index id i would return the wrong chunk even when its similarity score is correct. An own-text example could pass by coincidence if that chunk kept its position. The symptoms do not prove this is the only possible bug, but checking ids and chunk order is a useful first step.

FAQ



Why brute force instead of the IVF index I built last week?


The default corpus produces only 25 chunks, so exact search is inexpensive and needs no clustering. The provided microvector.py also contains IVF. For a larger corpus, compare exact and approximate search with explicit cluster and probe settings rather than assuming a fixed size threshold.



My hit@3 is 0.92, not 1.00. Is that a bug?


A hit@3 of about 0.92 is the reference result: one of the 12 questions is missed. The QUALITY thresholds, hit@3 ≥ 0.90 and MRR ≥ 0.70, allow that known limitation. If your score is lower, check chunk/index alignment, embedding inputs, result order, and configuration against the starter.



Where does the LLM actually come from?


The provided answer() function can call an OpenAI-compatible chat endpoint configured through environment variables. The course will provide details for in-class use. The graded tests use offline echo mode, so a model connection is not required to complete the lab.



Can my project just use this file?


Yes, this file provides a starting architecture. Replace the corpus, evaluate a learned embedder, choose an index for your scale, and create a domain-specific evaluation set. The project also requires evidence for those choices and evaluation of generated answers; passing this lab alone does not complete those requirements.
