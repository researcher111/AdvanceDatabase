The whole pipeline, one file



micro_rag.py is Tuesday's five-stage diagram as five
callables, in reading order:



chunk_corpus()   documents → chunks               provided   (record design, done for you)
embed(text)      text → 2048-dim unit vector      provided   (the hashing trick, read it)
Retriever        chunks → index → top-k           YOUR JOB   (Lab 9's index, wired to text)
build_prompt()   question + chunks → prompt       YOUR JOB   (context assembly, exact format)
answer()         prompt → text                    provided   (echo mode, or LLM_BASE_URL)



The provided embed deserves two minutes of reading: it is the whole
"embedding model" and it fits on a slide. Hover each line:





for word in re.findall(r"[a-z]+", text.lower()):
    if word in STOPWORDS:
        continue
    counts[word] = counts.get(word, 0) + 1


dim = int(hashlib.md5(word.encode()).hexdigest(), 16) % DIM


v[dim] += 1.0 / (1.0 + math.log(count))


norm = math.sqrt(sum(x * x for x in v)) or 1.0
return [x / norm for x in v]







That's a real embedder: the
hashing trick with
stop-word removal. Its real
limitation: it matches words, not meaning. The lab measures the limitation
instead of hiding it, and your project replaces this one function with a learned model
while keeping every other line.

  The shapes that matter
  
A chunk is {"doc": "wal", "title": "Write-ahead logging", "text": "Before
  changing a page…"}. Retriever.retrieve(question, k) returns k of those,
  each with a "score" added, best first. build_prompt turns them
  into three blank-line-separated sections: header, one [doc] Title: text line
  per chunk, then Question: …. The harness parses that format character by
  character; "close" is not a format.

  Gotchas that cost real debugging time
  
Attach scores to copies; mutating self.chunks passes one retrieval
  and corrupts the next (there's a test for exactly this). Embed the chunk's
  text, not title+text; the own-text test expects cosine 1.0. And keep
  build_prompt boring: no extra newline at the end, no numbering, no
  "creative" header. The format is an I/O protocol, like every autograder this
  semester.

  Exercise · read the failure
  
A classmate passes everything except the two QUALITY tests: hit@3 comes out 0.08.
  Their retrieve looks right, and the own-text test passes. What one
  line in __init__ produces exactly this pattern?

  
Show answer
  
They built the index from a re-sorted list (e.g.
  sorted(chunks, key=...) or a set-deduped copy) while self.chunks
  kept the original order. Index id i now points at the wrong chunk. The
  own-text test can still pass when the queried chunk happens to land at the same position;
  the eval set, which checks which doc came back, collapses to near zero. Alignment
  bugs are silent until something checks identity, not just scores; that's what eval sets
  are for.

Drag to shrink the embedding. Collisions merge unrelated words
  onto shared dimensions; the eval set watches quality fall. MRR
  falls first; collisions demote the right doc before they hide it.

Read the mini-eval before the top-3 lists. The hashed embedder finds
three of the ten papers, and in each of those the question happened to share an exact word with
the abstract (join tree, snapshot, transaction log). Where the
paraphrase used different words for the same idea, hashing has nothing to match and the paper does
not appear in the top ten at all. The model finds nine of ten, three at rank one, having never seen
these papers or questions: it learned that "pieces by meaning" and "semantic chunking" are near each
other. That difference is the entire case for a learned embedder, and it is measured, not asserted.
It is also why your project's evaluation questions must be written by people who read the corpus,
not generated from the titles.

FAQ



Why brute force instead of the IVF index I built last week?


25 chunks. IVF's bookkeeping costs more than it saves below a few
thousand vectors: Tuesday's "at small scale, brute force is the right answer," practiced.
The import swap is one line when your project corpus crosses that line; that's why
microvector.py ships whole.



My hit@3 is 0.92, not 1.00. Is that a bug?


No, that's the reference behavior. One eval question fails on a
word-form mismatch ("deleted" vs "Deleting"), and the bars (0.90 / 0.70) are set so the
correct implementation passes with the honest miss included. If you're at 0.83 or below,
suspect index/chunk misalignment, not the embedder.



Where does the LLM actually come from?


Any OpenAI-compatible chat endpoint. The course will post one for
in-class use, or run a local server (Ollama and vLLM both speak the protocol). Nothing in the
graded work needs it: the autograder runs entirely in echo mode, because what's graded is
retrieval, and the prompt is retrieval made visible.



Can my project just use this file?


That's the intent; it's the reference architecture. Swap
embed for a learned model, corpus.py for your documents,
BruteForceIndex for IVF/pgvector when scale demands, and grow the eval set to
your domain. The structure (five stages, one contract each, an eval set in the loop)
is the graded part of the project too.
